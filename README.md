# AR设备租赁

独立的原生微信小程序前端，API 目标为 `https://c.4mr.cn/api/v2`，服务端由原 `wechat` 项目维护，本仓库不包含后端实现。项目没有网页、H5 或 uni-app 运行依赖，无需前端构建。使用微信开发者工具直接导入本目录。

小程序上传和后端上线是独立操作。接入前须部署租赁后端、执行数据库迁移并配置新 AppID/AppSecret；接口返回 404 时应检查后端版本及代理路由，单独上传前端不会使接口上线。真实支付与退款还需开通微信支付并完成新 AppID 的商户关联。

## 配置和上传

1. 项目已绑定微信公众平台中 **AR设备租赁** 的 AppID：`wx03dbf50c15cac06f`。上传校验要求此准确 AppID，旧拍摄小程序及其他 AppID 都会被拒绝。
2. 后端配置新小程序 AppID、AppSecret 和微信支付商户关联。AppSecret、商户密钥及证书不放入本项目。前端不能修复后台未开通或未关联的支付权限。
3. 新小程序的 request 合法域名设置为 `https://c.4mr.cn`，保持 `urlCheck: true`。
4. 扫普通链接二维码规则 `https://c.4mr.cn/d` 指向 `pages/device/index`，例如 `https://c.4mr.cn/d?uuid=DEVICE_UUID&type=rokid`。入口校验微信传入的 `q` 并转入 `pages/device/scan`，完整保留 UUID 与可选 type；小程序内扫码统一使用此地址。UUID 在身份认证前显示，后端登录失败仍保留识别结果。微信后台规则未发布时需按其测试设置配置测试范围与具体测试链接，不能仅靠上传代码开放全网扫码。
5. 运行 `npm test` 和 `npm run validate-upload`，核验已绑定的真实 AppID。使用微信开发者工具导入本目录，编译并上传，再通过公众平台审核和发布。

## 页面

- 首页：扫码入口、当前登录账号及身份、管理入口。
- `pages/device/index`：普通链接二维码入口，与微信后台现有规则一致。
- `pages/device/scan`：设备状态、租赁支付、本人计时、他人占用、管理员结束和退款、费用配置与启停。
- 我的租赁、订单详情：待支付订单恢复、支付/退款结果查询。
- 设备管理：管理员搜索设备，进入统一设备页管理。
- 用户身份管理：root 授予或撤销 manager；普通用户和 manager 无法调用角色管理业务。

角色以新小程序后端登录返回及每次接口鉴权为准。新 App 有独立缓存键，不继承旧小程序的 OpenID 或本地付款记录。服务端通过可信身份关联共享用户。首次登录没有管理身份的账号不会自行提升权限；由现有 root 按用户 ID 授予。

## 资金与状态

价格、押金、退款金额和支付参数来自服务端。用户一次支付使用费和押金。客户端支付成功、取消或结果不明，都会请求服务端确认，界面没有本地“已支付”开关。网络写请求不自动重放，401 明确未授权时仅恢复登录并重试一次。

管理员结束时选择退押金或全额退款、填写原因并确认设备已归还。退款到原付款账户，设备在服务端确认退款成功后恢复可租。取消结束确认不发送结束请求。费用配置采用服务端版本防止覆盖其他管理员的修改；修改不改变既有订单快照。

页面隐藏或销毁时停止轮询及计时。付款流程若经历微信原生页面切换，会在返回后重新查询；离开页面后收到的预支付响应不会自动唤起支付。所有显示时间使用北京时间。

## 接口

`utils/api.js` 集中维护接口。登录是 `/rental/auth/login` / `/rental/auth/refresh`；设备租赁视图是 `/rental/devices/context`；租赁记录、支付、取消、结束和退款在 `/rentals` 下。租赁创建、管理员结束使用幂等键，金额均由服务端计算。后台可以返回 `paymentReady:false`，页面将暂时禁用付款。

## 测试

```sh
npm test
npm run validate-upload
```

测试模拟微信 API，不发起真实支付、退款或后端设备创建。开发工具真机验证支付与退款前，先完成新 App 与商户号的关联和后端配置。
